JSON Import

Upload cards from structured .json

Intended for card sets generated by AI/LLMs or other tools. This is additive and separate from full backup import.

Accepted JSON import format 
{
  "schema": "flashcram.cards.v1",
  "deck": "Deck name",
  "cards": [
    {
      "front": "Question",
      "back": "Answer",
      "tags": ["tag1", "tag2"],
      "format": "plaintext"
    }
  ]
}

Use format as plaintext or markdown. Backup JSON files should be imported from Settings.

Prompt for generating FlashCram JSON

Copy this into an LLM alongside your source notes.

Generate FlashCram flashcards as valid JSON only.

Output JSON only. Do not wrap the response in Markdown fences. Do not add commentary.

Use exactly this schema:

{
  "schema": "flashcram.cards.v1",
  "deck": "Deck name here",
  "cards": [
    {
      "front": "required question text",
      "back": "required answer text",
      "tags": ["lowercase", "tags"],
      "format": "plaintext"
    }
  ]
}

Rules:
- Use "plaintext" only for simple cards with no formatting needs.
- Use "markdown" whenever a card includes code, commands, inline code, multi-line examples, bullet lists, numbered lists, tables, equations, or LaTeX.
- Preserve useful code examples, formulas, definitions, and examples from the source material.
- Make each card atomic and exam-focused.
- Prefer multiple focused cards over one broad card.
- Keep tags lowercase, short, and reusable.
- Do not include ids, counters, timestamps, image fields, status fields, or backup/export fields.
- Ensure every card has non-empty front, non-empty back, a tags array, and a valid format.

JSON escaping rules:
- Output must be valid JSON.
- Inside JSON strings, encode line breaks as \n.
- Escape double quotes inside card text as \".
- Escape all LaTeX backslashes inside JSON strings.
- Correct: \\sum_{i}, \\frac{a}{b}, \\neg A, \\mid
- Incorrect: \sum_i, \frac{a}{b}, \neg A
- Escape inline LaTeX delimiters as \\(...\\) inside JSON strings.
- Do not use bare $...$ math.

Markdown formatting rules:
- Use a blank line before and after every Markdown block.
- Markdown blocks include bullet lists, numbered lists, fenced code blocks, display math blocks, and tables.
- Bullet lists must have a blank line before the first - item.
- Numbered lists must have a blank line before the first 1. item.
- Do not place a list, display math block, code fence, or table immediately after a sentence without a blank line.

LaTeX/math rules:
- Use \\(...\\) for inline math.
- Use $$...$$ for display math.
- Do not use \\[...\\] display math.
- Put display math on its own block with a blank line before and after it.
- Prefer explicit braces for subscripts and superscripts.
- Correct: \\sum_{i}, x_{i}, p_{i}
- Avoid: \\sum_i, x_i, p_i
- Use \\mid instead of raw | inside probability expressions where appropriate.
- Prefer: P(A \\mid X)
- Avoid: P(A|X)

Code formatting rules:
- For inline code, use backticks, e.g. `pthread_create()`, `ls -la`, `$HOME`.
- For multi-line code, use fenced code blocks with a language label where appropriate, e.g. c, bash, python.
- Shell variables like `$HOME`, `$PATH`, `$1`, and `$?` should stay literal inside inline code or fenced code blocks.
- Do not treat shell variables as LaTeX.

Example markdown card with math:

{
  "front": "What is the expected utility formula?",
  "back": "Expected utility is the probability-weighted sum of utility across possible outcomes.\n\n$$\nEU=\\sum_{i} p_{i}u(x_{i})\n$$\n\nThis means each outcome's utility is weighted by its probability.",
  "tags": ["economics", "utility", "expected-utility"],
  "format": "markdown"
}

Example markdown card with a list:

{
  "front": "List common explanations for giving in dictator-game-style experiments.",
  "back": "Common explanations include:\n\n- altruism\n- equality or fairness\n- warm glow\n- self-image\n- social norms of equal sharing\n- experimenter demand effects",
  "tags": ["economics", "behavioural-economics", "experiments"],
  "format": "markdown"
}

{
  "front": "Write a C snippet that creates a pthread using `pthread_create()`.",

  "tags": ["c", "threads", "pthread"],
  "format": "markdown"
}
